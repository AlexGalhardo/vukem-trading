SDD in this project means **Software Design Document**, used as a specification
for implementation and verification. Each SDD describes behavior, contracts,
failures, acceptance criteria and open items. It is not code already implemented.

| ID | Document | State |
| --- | --- | --- |
| SDD-01 | [Identity and dashboard](/docs/sdd/01-identity-dashboard) | Confirmed requirements; proposed details |
| SDD-02 | [Data and strategies](/docs/sdd/02-data-strategies) | Markets confirmed; feeds and parameters pending |
| SDD-03 | [Risk and execution](/docs/sdd/03-risk-execution) | Paper confirmed; policies and design proposed |
| SDD-04 | [Backtesting](/docs/sdd/04-backtesting) | Proposed |
| SDD-05 | [Railway and operations](/docs/sdd/05-railway-operations) | Destination confirmed; design proposed |
| SDD-06 | [Adapters and simulation](/docs/sdd/06-adapters-simulation) | Adapters confirmed; data pending |
| SDD-07 | [Daily ranking, backtest and paper runner](/docs/sdd/07-daily-ranking-and-paper-runner) | Implemented |

Changing a contract requires reviewing the associated ADR, data model, plan and tests.
